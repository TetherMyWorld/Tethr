# Phase 3 Core User Flows Checklist

## Goal

Make the highest-frequency flows low-friction, visually coherent, and implementation-ready.

This checklist corresponds to `Phase 3: Core User Flows` in [tethr-architecture.md](/F:/Tethr/TethrArca/docs/tethr-architecture.md).

## Checklist

### Search and navigation

- [x] Define the universal front-page search rule
- [x] Design the mixed-type search result card grammar
- [x] Design the iconic minimalist home page shell
- [x] Define the minimal account-access control for the home page
- [x] Decide that home search submits to a separate results page
- [x] Add an explicit submit/search action to the home page search
- [x] Design the separate results page shell
- [x] Define the default sort / ranking logic for search results
- [x] Decide how filters appear after mixed-type results load
- [ ] Decide whether `Mine only` is a first-version filter or a later search preference

### Quick Add

- [x] Define Quick Add flow
- [ ] Design the actual Quick Add surface(s) for web and mobile
- [ ] Decide what the smallest useful confirmation UI looks like
- [ ] Define the exact post-create success states per lane

### Add Event

- [x] Define Add Event flow
- [ ] Design the lightweight event composer
- [ ] Design the structured event/template variant
- [ ] Decide how new events appear in the subject timeline immediately after save

### Find / Move / Retrieve

- [x] Define Find / Move / Retrieve flow
- [x] Define scan move flow
- [ ] Design the focused move UI
- [ ] Design the quantity-update UI
- [ ] Define the first-version undo/success state for move actions

### Photo / Media

- [x] Define the canonical media model
- [x] Define subject-vs-event photo rules
- [x] Define crop interaction rules
- [ ] Design the shared upload UI grammar for all surfaces
- [ ] Decide whether multi-image support is first-version or later

### Output of this phase

- [ ] Phase 3 is complete when the core user flows can be designed and implemented from checklists rather than fresh architecture debate
